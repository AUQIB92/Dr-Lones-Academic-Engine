# V14 · L14–15 — Inter-Process Communication: How Processes Talk

> **Lecture:** CS502 L14 `14-semaphore-patterns-ipc` + L15 `15-ipc-systems` · **Unit:** II · **Target length:** 15–17 min · **Series position:** 14/28
> **Format:** mixed (screen-capture animation + code + terminal demo) · **Language:** English (Hinglish version optional)

## 1. Why this deserves a video

Inter-process communication is about data *moving* between two address spaces that the OS keeps
apart on purpose. On a slide, "shared memory" and "message passing" are two boxes; in a video we
can show bytes being copied through the kernel in one case and written straight into a shared
region in the other, and show who pays for synchronization in each. The pipe demo matters most:
students who read `pipe()` and `fork()` separately rarely understand why each process must close
the end it does not use, or why the reader gets "end of file". A real program, compiled and run on
camera, makes those rules visible.

## 2. Learning outcomes

After watching, the student can:
- [Understand] Contrast shared memory and message passing: who sets up the channel, who synchronizes, where the data is copied.
- [Remember] Classify message-passing designs by naming (direct/indirect), synchronization (blocking/non-blocking) and buffering (zero, bounded, unbounded capacity).
- [Apply] Write and trace a C program that sends a message from parent to child with `pipe()` and `fork()`, closing the correct ends.
- [Understand] Distinguish ordinary pipes, named pipes (FIFOs), message queues and sockets, and say when each fits.
- [Analyze] Choose an IPC mechanism for a given scenario (related vs unrelated processes, same machine vs network).

## 3. Prerequisites

- Basic computer fundamentals: main memory, files, what a C program and a terminal are, what a network connection is.
- V01–V03: the OS as a protected kernel; system calls (`read`, `write`) as the way a program asks the kernel for service.
- V05: process, PCB, each process has its own address space.
- V07: `fork()` creates a child that is a copy of the parent; `wait()`; return values of `fork()`.
- V10: race condition, critical section.
- V13: semaphores, `wait(S)` / `signal(S)`, blocking.

## 6. Worked example (verified)

**A. Demo program `pipe_demo.c`.**

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>
#define READ_END 0
#define WRITE_END 1
int main(void) {
    int fd[2];
    char buf[64];
    if (pipe(fd) == -1) { perror("pipe"); return 1; }
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }
    if (pid > 0) {                       /* parent = producer */
        close(fd[READ_END]);
        const char *msg = "Greetings from parent";
        write(fd[WRITE_END], msg, strlen(msg) + 1);
        printf("parent wrote %zu bytes\n", strlen(msg) + 1);
        close(fd[WRITE_END]);
        wait(NULL);
        printf("parent: child finished\n");
    } else {                             /* child = consumer */
        close(fd[WRITE_END]);
        ssize_t n = read(fd[READ_END], buf, sizeof buf);
        printf("child read %zd bytes: \"%s\"\n", n, buf);
        n = read(fd[READ_END], buf, sizeof buf);
        printf("child second read returned %zd (EOF)\n", n);
        close(fd[READ_END]);
    }
    return 0;
}
```

Compile and run (recorded run; `gcc` on this machine is Apple clang 21.0.0, macOS arm64; no
warnings with `-Wall`; exit status 0):

```
$ gcc -Wall -o pipe_demo pipe_demo.c && ./pipe_demo
child read 22 bytes: "Greetings from parent"
child second read returned 0 (EOF)
parent wrote 22 bytes
parent: child finished
```

- `"Greetings from parent"` is 21 characters; `strlen(msg) + 1` = **22** bytes including the `'\0'`.
- The second `read` returns **0**: all write ends are closed, so end of file.
- The line order between `parent wrote …` and the child's lines can change from run to run; only
  `parent: child finished` is guaranteed last (because of `wait(NULL)`). Narrate this, do not hide it.

**E. Decision table (scene 15).**

| Situation | Mechanism |
|---|---|
| Parent and child, one-way stream | ordinary pipe |
| Unrelated processes, same machine, byte stream | named pipe (FIFO) |
| Discrete messages with types/priorities | message queue |
| Large data, maximum speed, same machine | shared memory + semaphores |
| Processes on different machines | sockets (client–server) |

## 8. Misconceptions to address on screen

- "After `fork()`, parent and child share variables, so they don't need IPC." → Scene 2: the child gets a *copy*; changing `x` in the child leaves the parent's `x` unchanged.
- "Shared memory is synchronized by the OS." → Scene 4/5: the kernel dims after setup; races are the programmer's problem.
- "A pipe is two-way." → Scene 9: an ordinary pipe has one read end and one write end; two-way traffic needs two pipes.
- "Closing unused pipe ends is just tidiness." → Scene 11: the hang when the write end stays open.
- "Ordinary pipes work between any two processes." → Scene 12: only related processes; unrelated ones need a FIFO.
- "Message passing is always slower, so never use it." → Scene 4 and 14: it is the only choice across machines and is simpler to get right.
- "Non-blocking means the message is lost if nobody is listening." → Scene 7: it goes into the buffer (bounded/unbounded); with zero capacity a non-blocking send simply fails or returns at once.

## 11. End-of-video quiz

1. **(MCQ)** Which statement about shared memory is correct?
   (a) every read is a system call (b) the kernel synchronizes all accesses (c) after setup, accesses are ordinary memory operations and the processes must synchronize (d) it works between machines
   **Answer: (c).**
2. **(Numerical)** A circular buffer of size 12 uses the simple scheme where full means `(in+1) % 12 == out`. How many items can it hold at most? **Answer: 11.**
3. **(MCQ)** A parent calls `pipe(fd)` and then `fork()`. The parent will only write. Which descriptor should the parent close?
   (a) `fd[1]` (b) `fd[0]` (c) both (d) neither
   **Answer: (b).**
4. **(Numerical)** In the demo, the parent writes the string `"Hi OS"` with `strlen(msg) + 1` bytes. How many bytes does the child's first `read` return? **Answer: 6.**
5. **(MCQ)** Two unrelated programs on the same machine, started by different users at different times, must exchange a byte stream. Best fit?
   (a) ordinary pipe (b) named pipe (FIFO) (c) `fork()` (d) none is possible
   **Answer: (b).**
