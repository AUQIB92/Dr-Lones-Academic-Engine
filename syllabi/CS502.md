# Operating Systems (PCC CS-502) — B.Tech CSE, Semester 5

Undergraduate · 3 sessions/week (lecture) · 39 lectures · Credits 3 (L-T-P: 3-0-0)

Source: institute scheme, `syllabi/OS.pdf` (p. 69 of 142).

## Course description

This course builds a working model of what an operating system does and how it does it. Students move from the OS as a resource manager and the system-call interface, through process management and CPU scheduling, into the two classic hard problems of concurrency (mutual exclusion and deadlock), then through the memory hierarchy that turns a finite physical memory into an apparently private virtual address space per process, and finally into I/O management, disk scheduling, and the file system. The 39 lectures are grouped into the official four units; students leave able to reason about OS mechanisms — not just name them — by tracing a scheduling decision, proving a synchronization protocol correct, walking a page-fault handler, or ordering a disk-arm queue, and by selecting the right mechanism for a stated workload.

## Prerequisites

Programming in C (functions, pointers, arrays, structs, basic system calls); a working model of a single-process program and of the machine it runs on (CPU, registers, memory, I/O) — CS401 Computer Organization & Architecture or equivalent. Algorithms literacy (asymptotic cost, queues, lists) is assumed for the scheduling and page-replacement analysis.

## Learning objectives

By the end of this course, students will be able to:

- Describe the functions, evolution, structure, and services of an operating system, and use system calls and system programs as the interface between user programs and the kernel (Lectures 1–4)
- Represent a running program as a process — draw and interpret the process state diagram, explain the PCB, schedulers, and a context switch, and use process-creation system calls (Lectures 5–7)
- Apply and compare CPU scheduling algorithms (FCFS, SJF/SRTF, Round Robin, Priority, multilevel) against scheduling criteria, and describe multiprocessor scheduling (Lectures 8–9)
- Explain the principle of concurrency, state and solve the critical-section problem, and apply software/hardware solutions, semaphores, and monitors (Lectures 10–14)
- Explain inter-process communication (shared memory, message passing, pipes, sockets) (Lectures 14–15)
- Apply synchronization tools to the classical concurrency problems — bounded-buffer, readers–writers, dining philosophers (Lectures 16–17)
- Characterize a deadlock with the resource-allocation graph and the four necessary conditions, and apply prevention, avoidance (Banker's algorithm), detection, and recovery (Lectures 18–19)
- Compare contiguous memory-allocation techniques and their allocation strategies, and quantify fragmentation and compaction (Lectures 20–22)
- Explain non-contiguous allocation — paging, segmentation, address translation, and TLB performance — and virtual memory via demand paging (Lectures 23–26)
- Compare page-replacement algorithms (FIFO, Optimal, LRU, clock) and explain frame allocation and thrashing (Lectures 27–29)
- Describe I/O device organization, I/O techniques (polling/interrupts/DMA), the kernel I/O subsystem, and I/O buffering (Lectures 30–33)
- Apply disk-scheduling algorithms (FCFS, SSTF, SCAN, C-SCAN, LOOK, C-LOOK) to an arm-queue and analyze disk performance (Lectures 34–36)
- Describe file-system organization, file organization and access methods, directory structures, file sharing/protection, and file-system implementation (Lectures 37–39)
